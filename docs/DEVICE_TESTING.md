# Тестирование на реальных iPhone и Android

## 0. Быстрый старт: как увидеть приложения на телефонах

Самый короткий путь — **сначала Android** (для установки APK не нужен аккаунт Google Play), параллельно оформляется Apple.

| Шаг | Кто | Что сделать | Время |
|---|---|---|---|
| 1 | Вы | Арендовать сервер для тестового стенда: Yandex Cloud → Compute Cloud, Ubuntu 24.04, 2 vCPU / 4 ГБ / 30 ГБ, публичный IP, открыть порты 80, 443, 22 | 15 мин |
| 2 | Вы (или я по вашему доступу) | Выполнить 5 команд из `infra/stand/README.md` — стенд поднимется с HTTPS на бесплатном адресе `<IP>.sslip.io` | 15 мин |
| 3 | Вы | Создать бесплатный аккаунт на expo.dev и **токен доступа** (Account settings → Access tokens) — передать мне через защищённую форму, которую я пришлю (не в чат) | 5 мин |
| 4 | Я | Разрешить в настройках этой среды доступ к серверам Expo (запрошу подтверждение), `eas init`, собрать APK обоих приложений с адресом стенда | 30–60 мин сборки |
| 5 | Вы | Открыть ссылку на APK на Android-телефоне → установить → войти по номеру; код — в админке стенда «Система → Тестовые SMS» | 5 мин |
| 6 | Вы | Apple Developer Program: как физлицо — 1–2 дня; как компания — нужен D-U-N-S, 1–2 недели. Пригласить меня не нужно — достаточно войти в Expo под своим Apple ID при сборке | — |
| 7 | Я + вы | iPhone: зарегистрировать устройства (ссылка `eas device:create`, открыть на iPhone), собрать ad-hoc сборку; после этого — TestFlight для широкого круга | 1 день |

Демо-аккаунты для входа (после `seed`): заказчики `+7 900 000-05-01`, `+7 900 000-06-01`; партнёры —
`+7 900 000-01-01` (руководитель), `-01-02` (диспетчер), `-01-03` (машинист), `-02-01` (ИП-машинист), `-04-01` (независимый диспетчер).
Для проверки фонового GPS на одном телефоне войдите машинистом в «Партнёре», на другом — заказчиком.


Что уже подготовлено в коде, как собрать приложения для тестировщиков и что проверить на телефонах.
Всё, что здесь перечислено как «проверить», **ещё не проверено** — в браузере и эмуляторе эти функции не воспроизводятся.

## 1. Что нужно до начала

| Что | Кто | Зачем |
|---|---|---|
| Аккаунт Apple Developer (для компании — D-U-N-S) | заказчик (А-1) | сборки для iPhone, TestFlight |
| Аккаунт Google Play Console | заказчик (А-2) | внутреннее тестирование Android |
| Аккаунт Expo (EAS) с доступом для разработчика | заказчик или разработчик | облачная сборка без Mac и Android Studio |
| Тестовый стенд сервера, доступный из интернета по HTTPS | разработчик, после А-3 | телефоны должны достучаться до API |

**Тестовый стенд** — тот же сервер с `NODE_ENV=development` и тестовыми провайдерами (SMS, оплата, маршруты,
адреса, push, телефония). Реальные деньги не списываются. Коды входа тестировщики смотрят в админке:
**Система → Тестовые SMS** (только суперадминистратор; в рабочей версии раздела нет).

Временный вариант до облака: сервер на компьютере разработчика + HTTPS-туннель (например, на домен разработчика).
Без HTTPS iPhone не даст приложению обращаться к серверу.

## 2. Сборка

В каждом приложении (`apps/client`, `apps/partner`) есть `eas.json`:

| Профиль | Для чего | Как поставить на телефон |
|---|---|---|
| `development` | разработчикам: отладка, фоновый GPS | iPhone — после регистрации устройства (ad-hoc); Android — APK |
| `preview` | тестировщикам | iPhone — ad-hoc или TestFlight; Android — APK по ссылке |
| `production` | магазины | App Store / Google Play |

```bash
cd apps/partner            # или apps/client
npx eas-cli@latest init    # один раз: создаёт проект EAS, его projectId попадает в app.json
npx eas-cli@latest env:create --environment preview --name EXPO_PUBLIC_API_URL --value https://api-test.<домен>
npx eas-cli@latest build --profile preview --platform android   # APK для тестировщиков
npx eas-cli@latest build --profile preview --platform ios       # нужен аккаунт Apple
```

Номер сборки увеличивается автоматически (`appVersionSource: remote`). Версия приложения и адрес сервера
показаны на экране входа — указывайте их в отчётах об ошибках. Если сборка сделана без адреса сервера,
экран входа сообщит об этом.

**Expo Go не подходит** для проверки: в нём нет фоновой геолокации и push с нашим кодом — нужна сборка `development` или `preview`.

## 3. Что сделано в коде для устройств

| Область | Сделано |
|---|---|
| Фоновый GPS машиниста | фоновая задача (`expo-task-manager`); Android — служба переднего плана с уведомлением «Вы в пути к объекту» (тип `location`, требование Android 14); iOS — фоновый режим `location` и индикатор; точки копятся без сети и отправляются пачками; передача только от «Выехал» до «Прибыл» |
| Пояснение перед запросом фона | экран «Геолокация в пути» до системного запроса (требование Google Play «prominent disclosure» и App Review); можно продолжить без фона |
| Офлайн-статусы | «Выехал/Прибыл/Начал/Завершил» сохраняются на телефоне и уходят при появлении связи, без дублей (Р-18, П-15) |
| Push | регистрация токена после входа (Expo-токен при наличии projectId, иначе системный FCM/APNs); канал «Заказы» с высоким приоритетом на Android; нажатие открывает заказ / предложения / смену; при выходе устройство снимается с сервера. **Отправка с сервера — после выбора push-провайдера** |
| Разрешения | Android: только геолокация (в т. ч. фоновая — у партнёра), служба переднего плана, уведомления, интернет; убраны микрофон, запись во внешнее хранилище, поверх окон. iOS: тексты запросов на русском, флаг «без нестандартного шифрования» |
| Ссылки | `kovsh://o/<токен>` открывает заявку диспетчера в приложении заказчика; веб-версия — `https://<домен>/o/<токен>` (переменная сервера `CUSTOMER_WEB_URL`). Универсальные ссылки (https → приложение) — после домена |
| Иконки | фирменные иконки, адаптивные иконки Android, иконка уведомлений |

## 4. Матрица проверок на устройствах

Устройства: минимум iPhone (iOS 17+) и 2 Android (чистый Android 13+ и Xiaomi/Redmi с MIUI/HyperOS —
там агрессивное энергосбережение). Отдельно — телефон без сервисов Google (Huawei): push через FCM не работает.

### Машинист (приложение «Партнёр») — главное
| # | Сценарий | Ожидаемый результат |
|---|---|---|
| 1 | «Выехал» → пояснение → «Разрешить всегда» | на Android — постоянное уведомление «Вы в пути»; заказчик видит движение |
| 2 | В пути заблокировать экран на 15 минут | точки продолжают приходить (у заказчика «обновлено …» не старше ~1 мин) |
| 3 | В пути свернуть приложение и открыть навигатор | передача не прерывается |
| 4 | В пути принудительно закрыть приложение (смахнуть) | Android: служба продолжает или восстанавливается; iOS: передача может остановиться — **зафиксировать фактическое поведение** |
| 5 | Режим полёта 5 минут в пути, затем включить | заказчик видит «Нет связи», потом догоняющий трек; статусы, нажатые без сети, приходят по порядку |
| 6 | «Прибыл» | уведомление «Вы в пути» исчезает, передача прекращается |
| 7 | Отказ в разрешении геолокации | статус уходит без координат, приложение подсказывает включить |
| 8 | Xiaomi с энергосбережением по умолчанию | зафиксировать, нужна ли инструкция «не ограничивать приложение» |
| 9 | Расход батареи за час в пути | записать % — норма уточняется по факту |

### Диспетчер
| # | Сценарий | Ожидаемый результат |
|---|---|---|
| 10 | Новый заказ, приложение закрыто | push «Новый заказ» (после подключения провайдера); нажатие открывает предложения; таймер совпадает с серверным |
| 11 | Принять заказ, назначить машиниста | машинисту приходит push; смена появляется у него |
| 12 | Фото техники с камеры и документ PDF | загрузка, предпросмотр |

### Заказчик
| # | Сценарий | Ожидаемый результат |
|---|---|---|
| 13 | «Я на объекте — определить местоположение» | запрос разрешения, адрес подставляется |
| 14 | Оплата | открывается страница оплаты, после возврата статус обновляется |
| 15 | Звонок машинисту | открывается набор подменного номера (реальный звонок — после провайдера телефонии) |
| 16 | Ссылка из SMS на заявку диспетчера | открывается в браузере без входа; при установленном приложении — `kovsh://` ссылка открывает экран заявки |
| 17 | Push о статусах: найден исполнитель, выехал, прибыл, завершено | приходят, нажатие открывает заказ |
| 18 | Тёмная тема, крупный шрифт системы, маленький экран (iPhone SE) | интерфейс не ломается |

### Общие
Плохая сеть (3G), смена сети Wi-Fi ↔ мобильная, выход и вход под другим номером на том же телефоне
(push прежнему пользователю не приходят), обновление приложения поверх старой версии.

## 5. Что отмечать в отчёте

Номер сценария, телефон и версия ОС, версия приложения (экран входа), время, что ожидалось и что произошло,
скриншот или запись экрана. Для GPS — номер заказа: трек и времена точек видны в админке (заказ → GPS).
