# Первые шаги к тестированию на телефонах — пошагово

Три действия с вашей стороны. После шага 3 сообщите мне адрес стенда (его покажет шаг 2) — дальше собираю Android-версии.
Если на любом шаге что-то отличается от описания — остановитесь и пришлите скриншот или текст ошибки.

---

## Шаг 1. Сервер в Yandex Cloud (≈ 20 минут)

### 1.1. Ключ для входа на сервер (на вашем компьютере)

Windows 10/11 — откройте «PowerShell», Mac — «Терминал», и выполните:

```
ssh-keygen -t ed25519 -C kovsh-stand
```

На все вопросы нажимайте Enter. Затем покажите **публичную** часть ключа:

* Windows: `type $env:USERPROFILE\.ssh\id_ed25519.pub`
* Mac: `cat ~/.ssh/id_ed25519.pub`

Скопируйте всю строку, начинающуюся с `ssh-ed25519`. Файл без `.pub` (закрытый ключ) никому не передавайте.

### 1.2. Аккаунт и платёжный аккаунт

1. Откройте https://console.yandex.cloud и войдите через Яндекс ID.
2. Создайте платёжный аккаунт (физлицо — карта; юрлицо — реквизиты). Новым аккаунтам обычно даётся стартовый грант.
3. Откроется облако с каталогом `default` — работаем в нём.

### 1.3. Постоянный IP-адрес

Чтобы адрес стенда не менялся после перезапуска сервера:

1. В поиске консоли наберите **Virtual Private Cloud** → слева **IP-адреса** → **Зарезервировать адрес**.
2. Зона доступности: `ru-central1-a` → **Зарезервировать**. Запишите адрес (например `51.250.10.20`).

### 1.4. Виртуальная машина

**Compute Cloud** → **Создать виртуальную машину**:

| Поле | Значение |
|---|---|
| Образ | **Ubuntu 24.04 LTS** |
| Зона доступности | `ru-central1-a` |
| Диск | SSD, **40 ГБ** |
| Вычислительные ресурсы | своя конфигурация: **2 vCPU, гарантированная доля 100%, 4 ГБ RAM** (прерываемую ВМ **не** выбирать) |
| Сеть | подсеть по умолчанию; Публичный адрес → **Список** → адрес из шага 1.3 |
| Доступ | Логин: `kovsh`; SSH-ключ: вставьте строку из шага 1.1 |
| Имя | `kovsh-stand` |

Нажмите **Создать ВМ** и дождитесь статуса **Running**.

### 1.5. Порты

Если в настройках сети ВМ указана **группа безопасности**, откройте её → **Правила** → **Входящий трафик** и добавьте
три правила: протокол TCP, источник `0.0.0.0/0`, порты **22**, **80**, **443**.
Если группа безопасности не указана — ничего делать не нужно (трафик не ограничен).

## Шаг 2. Запуск стенда на сервере (≈ 30–40 минут, большая часть — ожидание сборки)

### 2.1. Подключение

На вашем компьютере (замените адрес на свой):

```
ssh kovsh@51.250.10.20
```

На вопрос `Are you sure you want to continue connecting` ответьте `yes`. Все следующие команды — в этом окне, по одной.

### 2.2. Подготовка сервера

```
sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker kovsh
exit
```

Файл подкачки нужен, чтобы сборке хватило памяти. После `exit` подключитесь снова (`ssh kovsh@…`) — так включится доступ к Docker.
Проверка: `docker ps` должен показать пустую таблицу без ошибки.

### 2.3. Код проекта

Репозиторий закрытый, поэтому нужен токен GitHub только на чтение:

1. В браузере: GitHub → аватар → **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
2. Name: `kovsh-stand`; Expiration: 90 days; Repository access: **Only select repositories** → ваш репозиторий проекта;
   Permissions → Repository permissions → **Contents: Read-only**. **Generate token** → скопируйте токен.

На сервере:

```
git clone -b claude/magical-bell-a63eao https://github.com/crazyyu866/-.git kovsh
```

Username — ваш логин GitHub, Password — **токен** (при вставке символы не отображаются — это нормально).

### 2.4. Настройки и запуск

```
cd kovsh/infra/stand
./init.sh
```

Скрипт покажет три адреса вида `https://api.51-250-10-20.sslip.io`. **Запишите их.** Затем:

```
docker compose up -d --build
```

Сборка занимает 15–30 минут. Проверка:

```
docker compose ps
```

У всех четырёх (`postgres`, `redis`, `api`, `web`) — статус `Up`, у `api` — `(healthy)`.
Если `api` перезапускается — пришлите вывод `docker compose logs api | tail -50`.

### 2.5. Демо-данные и ваш администратор

```
docker compose exec api node dist/demo/seed.cli.js
docker compose exec api node dist/admin/create-admin.cli.js ваш@email.ru "Ваше Имя" "Пароль-не-короче-12-символов"
```

Откройте в браузере **админку** (`https://admin.…sslip.io`), войдите по email и паролю, подключите приложение-аутентификатор
(Яндекс Ключ, Google Authenticator) по QR-коду — 2FA обязательна. Раздел **Система → Тестовые SMS** — здесь будут коды входа в приложения.

Если браузер пишет, что соединение не защищено, подождите 1–2 минуты (выпускается сертификат) и обновите страницу.

## Шаг 3. Аккаунт Expo (≈ 5 минут)

1. Откройте https://expo.dev/signup, зарегистрируйтесь (email, имя пользователя, пароль), подтвердите email.
2. Аватар → **Account settings** → **Access tokens** → **Create token**. Имя: `kovsh-build` → **Create**.
3. Токен показывается **один раз** — сохраните его у себя. **Не отправляйте токен в чат.**

## Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| `ssh: connect … timed out` | ВМ в статусе Running? Порт 22 открыт (шаг 1.5)? Адрес верный? |
| `permission denied` при `docker` | выйти (`exit`) и подключиться заново после шага 2.2 |
| ошибка скачивания образа `postgis` или `node` (429, timeout) | подождать 10 минут и повторить `docker compose up -d --build`; если повторяется — прислать текст |
| сборка оборвалась со словом `Killed` | памяти не хватило: проверить, что файл подкачки включён (`free -h`, строка Swap) |
| `api` не становится `healthy` | прислать `docker compose logs api | tail -50` |
